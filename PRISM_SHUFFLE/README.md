# PRISM SHUFFLE — 音楽・操作音セット仕様

音楽連動パズルゲーム(ルミネス/テトリスエフェクト系)用の素材一式です。
**この仕様書は実装する側が読む前提で書いています。**

---

## 0. 収録曲(4曲)

参考動画(RTA in Japan 2019 / ルミネス リマスター)を実測したところ、
タイムラインが盤面を1周する時間は**スキン(=曲)ごとに 4.0〜5.6 秒**と異なりました
(残差の小さい計測: 6:40 で 4.398秒 / 15:50 で 4.015秒 / 14:40 で 5.641秒)。
掃引の速さは曲のテンポで決まるのが本家の設計です。
そこでテンポの違う4曲を用意し、**プレイ中はレベルが5上がるごとに次の曲へ**切り替えます。
掃引は常に「2小節 = 16列」なので、BPM が決まれば掃引時間も決まります。

| 曲 | BPM | ジャンル | 調 | 1小節 | ループ長 | 掃引(2小節=16列) |
|---|---|---|---|---|---|---|
| **PRISM SHUFFLE** | 96 | ビッグビート / ファンク | F ドリアン | 2.5 s | 32小節 = 80.000 s (3,528,000) | **5.000 s** |
| **NEON MARCH** | 120 | 4つ打ちテクノ | A エオリアン | 2.0 s | 32小節 = 64.000 s (2,822,400) | **4.000 s** |
| **CIRCUIT RUSH** | 112 | エレクトロ・ブレイクス | E エオリアン | 2.142857 s | 32小節 = 68.571429 s (3,024,000) | **4.286 s** |
| **GLASS TIDE** | 84 | ダウンテンポ・ダブ | D ドリアン | 2.857143 s | 32小節 = 91.428571 s (4,032,000) | **5.714 s** |

BPM はすべて **32小節ぶんが 44.1kHz でサンプル単位に割り切れる値**を選んでいます
(32小節 = 7680/BPM 秒、7680×44100 = 2^11·3^3·5^3·7^2 の約数)。
端数が出るとループのたびに位相がずれ、掃引と音が少しずつずれていくためです。

4曲とも構成は同じ 32小節 / 5ステムで、ピーク 0.94・各層の RMS も揃えてあります
(曲が変わるたびに音量が跳ねると疲れるため)。

### ファイル配置

```
PRISM_SHUFFLE/
  stems/ stems_web/ PRISM_SHUFFLE_loop.*   … PRISM SHUFFLE(96BPM)
  NEON_MARCH/stems_web/  NEON_MARCH/loop.*
  CIRCUIT_RUSH/stems_web/ CIRCUIT_RUSH/loop.*
  GLASS_TIDE/stems_web/  GLASS_TIDE/loop.*
  sfx/                                      … 操作音(全曲共通)
```

`stems_web/` には **m4a(AAC)** と **ogg(Vorbis)** の両方を置いています。
AAC は iOS Safari に必須、Vorbis は AAC を持たないビルド向けで、しかも小さい。
実装側は `canPlayType` で使える方を選び、片方だけを取得します。

新曲の原音 WAV は 260MB あり配信に使わないのでリポジトリには含めていません。
`tools/compose.py` で再生成できます(`tools/encode.py` で配信用に符号化)。

## 1. グリッド定数(PRISM SHUFFLE / 96 BPM)

| 項目 | 値 |
|---|---|
| テンポ | **96 BPM** |
| 1拍 | 0.625 秒 |
| 1小節 | 2.5 秒(4拍) |
| 16分音符 | 0.15625 秒 |
| ループ長 | **32小節 = 80.000000 秒**(サンプル数 3,528,000 @ 44.1kHz) |
| スウィング | 裏16分を **18.75 ms** 後ろへ(16分の12%) |
| 調 | **F ドリアン**(F G A♭ B♭ C D E♭) |
| 操作音の音階 | **C マイナーペンタトニック**(C E♭ F G B♭) — F ドリアンの部分集合 |

操作音は1セットしか持たず、曲が変わったら `audio.js` が再生レートで主音ぶん移調します(PRISM SHUFFLE を 0 として NEON MARCH +4 / CIRCUIT RUSH -1 / GLASS TIDE -3 半音)。
移調後もペンタトニックのままなので、A エオリアン / E エオリアン / D ドリアンのどれにも乗ります。

### 回転・落下の音(2026-08 作り直し)

初版はサイン波のブリップと逆再生スイープで、曲の上では「別の場所で鳴っている電子音」に聞こえていました。プレイヤーの操作音は曲のアクセントとして鳴るべきなので、`tools/sfx.py` で打楽器として作り直しています。

| 音 | 作り | 長さ |
|---|---|---|
| `rotate_cw` / `rotate_ccw` | ノイズのアタック + 非整数倍音(2.76倍)の金属バー + 5度と8度の重ね。CW=G5 / CCW=C5 の完全4度違い | 270 ms |
| `hard_drop` | 2オクターブ下降してサブに着地。同時にノイズが3帯域のクロスフェードで閉じる | 330 ms |
| `lock` | リム(1.4-4.2kHz) + 低いタム。連打で濁らない長さ | 230 ms |
| `move_left` / `move_right` | 軽いリム + 木の短い余韻 | 170 ms |

作り直し: `python3 tools/sfx.py && python3 tools/embed_sfx.py`


ループは**サンプル単位で正確に32小節**、継ぎ目のクリックなしを検証済みです。

> 初版は 135 BPM でしたが、「タイムラインの1周を 5 秒にしたい」という要件から
> 96 BPM へ作り直しました(16列 = 2小節を保つと 8拍 = 5.000 秒 → 96.000 BPM ちょうど)。
> 2小節は32小節ループを割り切るので、曲の切り替わりと掃引の頭が常に一致します。
> 素材は 135 BPM 版からの作り直しで、ドラムは16分のオンセットで切って
> 新しいグリッドへ貼り直し(アタックは無変化)、他はフェーズボコーダで音程を保って伸長。
> ボコーダは位相打ち消しで約3割痩せ、スライス貼り直しは尾が重なって約3割太るため、
> 層ごとに元の RMS へ戻してからピークだけリミッタで抑えています。

### 操作音のクオンタイズ

プレイヤー入力を音楽グリッドに吸着させる場合:

```
16分グリッド: t_q = round(t / STEP) * STEP        (STEP = 1拍/4、曲ごとに異なる)
スウィング適用: 奇数番目の16分は +STEP*0.12 秒
```

掃引は「1列 = 8分音符」、つまり16列で2小節ちょうどです。

## 2. 音楽ステム(`stems/`)

| ファイル | 内容 | 想定される投入タイミング |
|---|---|---|
| `01_drums.wav` | キック/クラップ/ハイハット/パーカッション | 常時 |
| `02_bass.wav` | ベース+サブベース | 常時 |
| `03_chords.wav` | コードスタブ+ローズ | レベル2〜 |
| `04_melody.wav` | メインフック | レベル3〜 |
| `05_atmos.wav` | パッド+高域のノイズ層 | 常時(後述) |

**全ステムが同じ32小節ループです。**同時再生すれば位相まで一致します。

**重要:** `sum(全ステム)` が `loop` と完全一致します。
`tools/master.py` で仕上げ直した素材では、非線形な処理も
「合計から求めたゲイン曲線」を全ステムへ同じように掛けているので、
以前のような 8% のヘッドルーム（×1.083）は不要になりました。

**`05_atmos` は常時鳴らすことを推奨します。**このステムには連続した高域ノイズ層が
入っており、ハイハットの刺さりを抑える役割を持っています。これを切ると高域が
むき出しになり、長時間プレイで耳が疲れます(実測で確認済みの現象です)。

### 段階的な盛り上げの例

```
静か  : 01 + 02 + 05
標準  : 01 + 02 + 03 + 05
高揚  : 01 + 02 + 03 + 04 + 05   (全部)
```

フェードは小節境界(1.777778秒の倍数)で、0.2〜0.4秒のクロスフェードを推奨します。

## 3. 操作音(`sfx/` 27種)

**全て F マイナーペンタトニック**です。半音も三全音も含まないため、
**プレイヤーがどのタイミングで何個同時に鳴らしても濁りません。**
音楽は F ドリアンですが、ペンタトニックはその部分集合なので衝突しません。

音域は **C5(MIDI 72)以上**に配置してあります。曲のメロディは意図的に
低め(中央値 MIDI 59 前後)に書いてあるので、操作音の居場所が空いています。

| ファイル | 音程 |
|---|---|
| `move_left` | C5 (72) |
| `move_right` | D#5 (75) |
| `rotate_cw` | F5 (77) |
| `rotate_ccw` | D#5 (75) |
| `soft_drop` | C5 (72) |
| `hard_drop` | C6 (84) |
| `lock` | C5 (72) |
| `invalid` | - |
| `clear_1` | G5 + C6 |
| `clear_2` | G5 + C6 + F6 |
| `clear_3` | G5 + C6 + F6 + A#6 |
| `clear_4` | G5 + C6 + F6 + A#6 + D#7 |
| `combo_01` | F5 (77) |
| `combo_02` | G5 (79) |
| `combo_03` | A#5 (82) |
| `combo_04` | C6 (84) |
| `combo_05` | D#6 (87) |
| `combo_06` | F6 (89) |
| `combo_07` | G6 (91) |
| `combo_08` | A#6 (94) |
| `combo_09` | C7 (96) |
| `combo_10` | D#7 (99) |
| `combo_11` | F7 (101) |
| `combo_12` | G7 (103) |
| `level_up` | C5 + F5 + A#5 + C6 + F6 |
| `stage_clear` | F4 + G#4 + C5 + D#5 + G5 + C6 |
| `game_over` | C5 下降スイープ |

### 連鎖(combo)の使い方

`combo_01` から `combo_12` は**ペンタトニックを1段ずつ上行**します。
連鎖数に応じて順に鳴らすと、そのまま上昇フレーズになります。
13連鎖以上は `combo_12` を繰り返すか、オクターブ上げてください。

### ライン消去

`clear_1` 〜 `clear_4` は消去ライン数に対応し、**多いほど和音が厚く高く**なります。

## 4. ミックスの実測値

作者の好きな3曲（長沼英樹 / Jet Set Radio・JSRF）を `tools/analyze.py` で測り、
その値へ `tools/master.py` で寄せてあります。測り方・差の内訳・
なにを直したかは **[ANALYSIS.md](ANALYSIS.md)** にまとめました。

| 指標 | 仕上げ直し後 | 参考3曲 |
|---|---|---|
| ラウドネス | −11.9 前後 | −11.0〜−11.6 |
| クレストファクター | 11.8〜12.3 dB | 11.9〜12.3 dB |
| スペクトル傾き | −3.4〜−3.9 dB/oct | −3.3〜−4.0 dB/oct |
| 高域の床 | 0.36〜0.61 | 0.12〜0.36 |
| ステレオ side/mid | −10 dB 前後 | −9.2〜−12.7 dB |
| 打点/持続 | −3.2〜−5.7 dB | −2.2〜−3.6 dB |

**高域の床（wash）** は「高域が連続した層として鳴っている度合い」です。
初版は 0.49〜0.89 と高く、これが「常時サーッと鳴っていて抜けがない」原因でした。
下向きエキスパンダで床だけを下げ、ハットが閃光のように立つようにしています。

**打点/持続 比**だけは参考曲まで届いていません。理由は編曲そのもので、
埋めるには素材を刻んで足す必要があります（ANALYSIS.md 5節）。

## 5. 再生成

```
python3 tools/compose.py                        # NEON / CIRCUIT / GLASS の原音
python3 tools/master.py --learn <参考曲...>      # 目標カーブを学習（済み）
python3 tools/master.py --out <出力先> <ステム>  # 仕上げ直す
python3 tools/encode.py                         # m4a + ogg にする
python3 tools/sfx.py && python3 tools/embed_sfx.py   # 操作音
```

必要なのは Python + numpy + scipy + imageio-ffmpeg だけです。

- `tools/compose.py` — NEON MARCH / CIRCUIT RUSH / GLASS TIDE の全ソース。
  `Song(name, bpm, swing, seed)` と各曲の関数を書き換えれば作り直せます。
- `tools/master.py` — 仕上げ。狙い値は `GOAL`、目標カーブは
  `tools/master_target.json`（`--learn` で作り直せます）。
- `PRISM_SHUFFLE/build.py` — 初代 PRISM SHUFFLE(135BPM版)のソース。
  外部の `synth` モジュールに依存していて現状は再実行できません。
  96BPM 版のステム（`stems/`）はリポジトリに入っているので、
  そこから `master.py` で仕上げ直せます。
