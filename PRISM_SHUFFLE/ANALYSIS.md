# 参考曲の解析と、ゲーム内曲の仕上げ直し

作者の好きな3曲（長沼英樹 / Jet Set Radio・Jet Set Radio Future）を
`tools/analyze.py` で測り、同じ物差しでゲーム内の4曲を測って、
差が出たところを `tools/master.py` で埋めた記録です。

**旋律・和音進行・リズムパターンは一切写していません。**
写したのは「人がその曲を良いと感じる原因になっている物理量」だけで、
しかも 1/2 オクターブまで均した粗い量しか使っていません。
この粒度では旋律の情報は完全に消え、音色の傾向だけが残ります。

---

## 1. なにをどう測ったか

| 測ったもの | 方法 | 人が感じるもの |
|---|---|---|
| テンポ | オンセット包絡の自己相関 + 裏拍の強さでオクターブ誤りを補正 | 速さ |
| スウィング | 打点時刻を1拍で折り返したヒストグラムの、裏16分の山の位置 | ハネ具合 |
| グルーヴ | キック/スネア/ハットの帯域ごとに、1小節を16分割した打点の強さ | ノリの骨格 |
| キー・コード | クロマ → Krumhansl-Schmuckler、小節ごとに最も近い和音 | 明るさ・切なさ |
| 帯域バランス | フレーム平均パワースペクトルを 1/2 オクターブに束ねる | 音の厚み・近さ |
| スペクトル傾き | 100Hz〜12kHz を 1/3 オクターブに束ねて直線当てはめ | 明るさ |
| クレスト | 0.4秒窓のピーク/実効値の中央値 | パンチ・迫力 |
| ラウドネス | K特性の簡易版で積分 | 音量感 |
| 高域の床 | 8kHz 以上の包絡の (10パーセンタイル / 中央値) | きらびやかさ vs もやつき |
| 打点/持続 比 | HPSS（時間方向/周波数方向のメディアンフィルタ）のエネルギー比 | 推進力 |
| ステレオ幅 | side/mid の実効値比 | 広がり vs 芯 |
| 展開の速さ | 小節ごとの特徴量の自己相似から切り替わりを数える | 飽きにくさ |

`python3 tools/analyze.py <音声ファイル...>` で誰でも再現できます。

### 測定でつまずいた点（同じ罠を踏まないために）

- **テンポは必ず「半分」に引っ張られる。** 自己相関だけだと拍が少ないほど
  1拍あたりの打点が強く見えるため。裏拍にも同じくらい打点があるかを見て
  倍テンポへ昇格させると、3曲とも実際の値（129.2 / 107.7 / 139.7）になった。
- **スペクトル傾きを1発のFFTで測ってはいけない。** 音数の少ない曲では
  「音符の谷間（ノイズ床）」の傾きを測ってしまう。フレーム平均のパワーで
  測り直したところ、ゲーム曲の傾きは −1.8 ではなく −3.8 前後だった
  （つまり最初の測定は誤りで、明るさは元から足りていた）。

## 2. 参考3曲の実測値

| 指標 | Like It Like This Like That | Teknopathetic | Sweet Soul Brother |
|---|---|---|---|
| BPM | 129.2 | 107.7 | 139.7 |
| キー | B♭ メジャー系（Gm/B♭maj7/Dm7 が循環） | B マイナー | G メジャー |
| ラウドネス | −11.0 | −11.6 | −11.3 |
| クレスト | 12.1 dB | 12.3 dB | 11.9 dB |
| スペクトル傾き | −4.01 dB/oct | −3.43 dB/oct | −3.26 dB/oct |
| 高域の床 | 0.185 | 0.122 | 0.357 |
| 打点/持続 | −2.4 dB | −3.6 dB | −2.2 dB |
| ステレオ side/mid | −12.7 dB | −10.4 dB | −9.2 dB |
| 展開の切替 | 12.7 秒ごと | 17.8 秒ごと | 11.2 秒ごと |

**3曲に共通していたこと**（＝作者が「好き」と感じている共通項）:

1. **ラウドネスとクレストが揃っている。** −11.3 LUFS 前後 / クレスト 12.1dB 前後。
   これは「常に密度が高いが、潰れてはいない」状態。
2. **1〜2kHz が痩せていない。** 管楽器・声のチョップ・スネアの芯がここにある。
3. **高域は「連続したノイズ」ではなく「短い閃光」。** 床が低く、
   ハットやスクラッチだけが突き抜ける。
4. **ステレオは意外に狭い。** side/mid −9〜−13dB。芯が真ん中にある。
5. **コードが小節ごとに動く。** maj7 / m9 / sus4 が当たり前に混ざる。
6. **10〜18秒ごとに展開が変わる。** 4〜8小節で必ず何かが入れ替わる。

## 3. ゲーム内4曲との差（仕上げ直し前）

| 指標 | 参考3曲 | ゲーム4曲 | 差 |
|---|---|---|---|
| ラウドネス | −11.0〜−11.6 | −13.7〜−15.1 | **2.5〜3.7 dB 小さい** |
| クレスト | 11.9〜12.3 | 11.9〜13.4 | ほぼ一致 |
| スペクトル傾き | −3.26〜−4.01 | −3.81〜−4.22 | やや暗い |
| 1〜2kHz | −9〜−12 dB | −15〜−18 dB | **5〜6 dB へこんでいる** |
| 20〜60Hz | −13〜−16 dB | −5〜−11 dB | **6〜10 dB 多い** |
| 高域の床 | 0.12〜0.36 | 0.49〜0.89 | **2〜4倍高い** |
| 打点/持続 | −2.2〜−3.6 | −4.5〜−6.0 | **1〜3 dB 弱い** |
| ステレオ side/mid | −9.2〜−12.7 | −4.1〜−7.6 | **広げすぎ** |
| 展開の切替 | 11〜18秒 | 9〜19秒 | 一致 |

聞こえ方に翻訳すると:

- **1〜2kHz の欠け + 20〜60Hz の過多** → 「遠くでもこもこ鳴っている」
- **高域の床が高い** → 「常時サーッと鳴っていて、抜けがない」
- **打点が弱い** → 「前に進む感じがしない」
- **ステレオが広すぎる** → 「芯がなく、スマホのスピーカだと消える」
- **ラウドネスが低い** → 「効果音に負ける」

## 4. なにを直したか（`tools/master.py`）

段の順番には意味があります。

1. **ドラム +4 dB**（打点/持続 比を寄せる）
2. **帯域バランス** — 参考3曲の 1/2 オクターブカーブの中央値へ、±4.5dB 以内で寄せる
3. **ステレオ幅** — side/mid を −10dB へ。150Hz 以下はモノ（スマホ対策）
4. **トランジェント** — 立ち上がりを 1.6倍まで、控えめに立てる
5. **サチュレーション** — クレストを 12.1dB へ。ピークを 0.94 に固定して
   クレストを合わせると、実効値＝ラウドネスも自動的に参考曲並みになる
6. **高域の床下げ** — 8kHz 以上を下向きエキスパンダで。**コンプの後**でないと
   コンプが谷を持ち上げ直して打ち消される
7. **リミッタ + 正規化**

### 結果（配信用 m4a を測り直したもの）

| 曲 | ラウドネス | クレスト | 傾き | 高域の床 | 打点/持続 |
|---|---|---|---|---|---|
| PRISM SHUFFLE | −14.3 → **−12.2** | 11.9 → **12.0** | −4.22 → **−3.96** | 0.85 → **0.53** | −4.5 → **−3.2** |
| NEON MARCH | −13.7 → **−12.2** | 12.9 → **12.3** | −3.81 → **−3.58** | 0.65 → **0.38** | −6.0 → **−5.7** |
| CIRCUIT RUSH | −14.1 → **−12.1** | 13.4 → **12.4** | −3.90 → **−3.63** | 0.89 → **0.50** | −4.8 → **−4.1** |
| GLASS TIDE | −15.1 → **−12.5** | 11.9 → **11.6** | −4.00 → **−3.53** | 0.48 → **0.35** | −5.7 → **−4.9** |
| （参考3曲） | −11.0〜−11.6 | 11.9〜12.3 | −3.26〜−4.01 | 0.12〜0.36 | −2.2〜−3.6 |

ステレオ幅は4曲とも −4.1〜−7.2 dB から **−10 dB 前後**へ揃いました。

ゲーム側では `audio.js` の `HEADROOM` を 1.083 → 0.86 にしています。
仕上げ直しでステムの合計がそのまま本体になった（従来の 8% ヘッドルームが不要になった）ぶんと、
ラウドネスが約 +2.1 dB 上がったぶんを引いて、効果音との音量バランスを元と揃えるためです
（差し引きで曲は約 +0.8 dB）。

### 実装でつまずいた点

- **ピーク正規化してはいけない。** EQ を掛けると必ず数サンプルだけ 1.5 まで跳ねる。
  そこを基準に割ると曲全体が 4dB 小さくなる。**リミッタで丸めてから**正規化する。
- **クレストをコンプで合わせようとすると失敗する。** アタックが通り抜けて
  ピークが下がらず、それ以外だけが潰れる。飽和（tanh）なら drive に対して
  クレストが単調に下がるので確実に追い込める。
- **飽和の効き目は「その後のリミッタまで通した状態」で評価する。**
  そうしないと必ず潰しすぎになる。
- **高域の分離は `filtfilt`（ゼロ位相）で。** 因果フィルタだと
  「元 − 高域」が本当の低域にならず、位相のずれた高域が残って床が下がらない。
- **ループ曲は前後に反対側の端を貼ってから処理する。** そうしないと
  フィルタの立ち上がりが曲の先頭に残り、1周目だけ音が違う。

ステム間の加算関係は壊していません。非線形な処理は「合計から求めたゲイン曲線」を
全ステムへ同じように掛けるので、**処理後のステムの合計＝処理後の本体**です。

## 5. 埋まらなかった差

**打点/持続 比**は、NEON MARCH / CIRCUIT RUSH / GLASS TIDE では
−5.7 前後にとどまりました（狙い −3.4）。ステムの音量をいじっても動きません
（コードやパッドを下げるとむしろ悪化することを確認済み）。

理由は編曲そのものです。参考曲は生音のコラージュで全パートが打点的なのに対し、
こちらはシンセの持続音が主体で、ベースやキックの胴鳴りが「持続音」に分類されます。
ここを埋めるには、**チョップした短い素材を刻んで足す**という編曲側の変更が要ります。

PRISM SHUFFLE だけは −3.2 まで届きました（元の素材がいちばん打楽器寄りのため）。

**高域の床**も PRISM SHUFFLE と CIRCUIT RUSH は 0.50 前後どまりです。
`05_atmos` が連続した高域ノイズ層を持っているためで、
これ以上エキスパンダを強めると、その層自体がポンピングして聞こえます。
0.85 → 0.53 で「もやつき」はかなり取れているので、ここで止めています。

## 6. 再現手順

```
python3 tools/analyze.py <音声ファイル...>          # 測る
python3 tools/master.py --learn <参考曲...>         # 目標カーブを学習
python3 tools/compose.py                            # 新曲3本の原音を作る
python3 tools/master.py --out <出力先> <ステム>      # 仕上げ直す
python3 tools/encode.py                             # 配信用に符号化
```

`MASTER_VERBOSE=1` を付けると、段ごとの測定値が出ます。
